## Overview

`Access` exists so that a class being serialised has exactly one thing to befriend. Writing
`friend class GPlatesScribe::Access;` lets the scribe reach a client's *private*
`transcribe()` method, its static `transcribe_construct_data()` and its static
`relocated()` — without opening the class to `Scribe`, to the free-function templates in
`Transcribe.h`, or to whatever else the library grows later. Every member is private and
the class is never instantiated; access is granted from the inside, to the free templates
`transcribe`, `transcribe_construct_data`, `relocated` and their `_impl` variants, plus
`ConstructObject` and `Scribe`.

Beyond forwarding, it supplies the two things only a friend can do. It constructs client
objects in place: `construct_object()` is placement `new` over a caller-supplied buffer,
generated by the preprocessor for zero to
`GPLATES_SCRIBE_ACCESS_CONSTRUCT_MAX_CONSTRUCTOR_ARGS` (10) constructor arguments taken by
const reference, which is how `ConstructObject` builds an object out of constructor data
just loaded from the archive. And it detects the intrusive hooks: the metafunctions
`HasStaticMemberTranscribeConstructData` and `HasStaticMemberRelocated` are what
`TranscribeImpl.h` uses to decide between a class's own static method and the non-member
default. They have to live here rather than in a standalone traits header because forming
the expression `&ObjectType::transcribe_construct_data` on a private member is itself a
privileged act.

The other half of the file is the export-registration anchor. `EXPORT_REGISTERED_CLASSES`
is a static initialised by calling `export_register_classes()`, whose body is not in
`ScribeAccess.cc` at all — it is a macro expanded from `ScribeExportRegistration.h`, because
the `gplates` executable, `pygplates` and the unit-test binary each register a different set
of classes. `Scribe` holds a reference to this static purely so the linker keeps the
translation unit.

## Notes

Compile errors reported *inside* this file are almost always a defect in the client class,
not here: the bodies of `Access::transcribe()`, `Access::transcribe_construct_data()`,
`Access::relocated()` and `Access::construct_object()` carry the diagnosis in comments —
a missing `friend class GPlatesScribe::Access;`, a missing `transcribe()` overload, or a
type with no default constructor and no `transcribe_construct_data()`. The same applies to
errors surfacing in the two `HasStaticMember*` metafunctions, which instantiate pointers to
private static members.

A constructor taking more than ten arguments cannot be reached through `construct_object()`
without raising `GPLATES_SCRIBE_ACCESS_CONSTRUCT_MAX_CONSTRUCTOR_ARGS`. All arguments are
taken by const reference; a non-const reference parameter has to be smuggled through a
`LoadRef` or `boost::ref`.

`EXPORT_REGISTERED_CLASSES` is a namespace-scope static with a dynamic initialiser, so
anything that runs before `main` and expects the export registry to be populated is subject
to static initialisation order. `Scribe`'s constructor binds a reference to it, which is
also the only reason this object file survives linking — see the note on
`d_exported_registered_classes` in [Scribe](Scribe.md).

The MSVC warning suppression around `construct_object()` is load-bearing for POD types:
`new (object) ObjectType()` value-initialises, and C4345 fires on exactly that.
